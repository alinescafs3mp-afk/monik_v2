# V16: спокойное обновление интерфейса и диагностика ping

## Что изменилось для оператора

Пустое поле «Путь и query» НЕ означает, что здоровье приложения не настроено. Оно лишь оставляет путь исходного URL. Условия успешного ответа задаются отдельно. В короткой строке теперь достаточно `HTTP 200 · 1 мс`; фраза про отсутствие настройки прикладного здоровья убрана.

Для обычной проверки HTTP 200..399 является успешным ответом и показывает зелёную лампу. HTTP 4xx/5xx и ошибка соединения показывают красную. Уже заданные условия не забываются: `ready=false` при HTTP 200 остаётся ошибкой; явно разрешённый владельцем иной код сохраняет смысл. Отключённая проверка обозначается пустой неактивной лампой, а не фиктивным отказом. Свежесть и наличие измерения не скрываются ради зелёного экрана.

Обычный пятисекундный опрос больше не должен двигать страницу, перехватывать фокус, стирать ввод или мигать кнопкой «Обновить». Нажатие «Настроить запрос» по-прежнему явно открывает нужный редактор. Ручное обновление имеет собственный отклик. Ошибки соединения остаются видимыми.

Быстрые измерения считаются устаревшими после 20 секунд, а не 15. Для более редких проверок сохраняются три их интервала. Это запас для доставки данных и фонового чтения, а не отключение контроля. Визуальный возраст больше не привязан к неправильным часам браузера/телевизора. При смене конфигурации необходимо дождаться результата НОВОЙ проверки. Строгий контроль свежести при раскатке обновлений остаётся 15 секунд.

В строчном обзоре имя и CPU/RAM/DISK/ping собраны слева, справа от них идут столбцы выбранных сервисов, по три сверху вниз. Количество столбцов зависит от доступной ширины. Не поместившиеся выбранные сервисы можно раскрыть явно; мониторинг от этого не меняется. Мобильная и телевизионная плотности сохраняются.

## Ping: один раз довести права установленной службы

V15 создавала отдельного пользователя monik, но не предоставляла резервный доступ к raw ICMP. На части систем ping-сокеты разрешены без него, на части нет. Без журналов первой машины нельзя утверждать, что именно это единственная причина отсутствия ping.

V16 показывает конкретное состояние: ping выключен; ещё нет измерения; ICMP запрещён службе; пакет не удалось отправить; пакет отправлен, но ответов нет. Среднее считается за последнюю минуту только по настоящим ответам. Отсутствие ответа не превращается в 0 мс. Смена цели не смешивает измерения разных адресов.

Для НОВОЙ установки правильные параметры уже входят в генератор systemd unit и новые шаблоны одного файла. Для УЖЕ установленной V15 замены бинарника недостаточно: Гроку нужно один раз применить права службы на соответствующем пилоте.

Проверяемый файл: `scripts/repair-icmp-linux.sh`. Запускать после просмотра только на нужной Linux-машине:

```sh
sudo bash repair-icmp-linux.sh
```

Это самостоятельный файл, его не требуется сопровождать всем исходным репозиторием. Он проверяет системный systemd и User=monik у monik-agent.service, создаёт ограниченный drop-in, перезапускает только эту службу и выводит фактические свойства. Регистрацию, CA, адрес, имя, конфигурацию и историю он не трогает. Остальные службы, firewall и глобальные sysctl не меняются. Если используется другой unit/пользователь, скрипт отказывает: кастомную установку нужно проверять отдельно.

CAP_NET_RAW даёт доступ к raw-сокетам, а не только к одному IP или одному типу пакета. Агент остаётся непривилегированным пользователем, NoNewPrivileges сохраняется. На VPS/контейнере провайдер может запрещать capability или ICMP; в таком случае этот шаг не является гарантией ответа от 8.8.8.8. Проверить надо реальный результат на машине, не только наличие строк в unit.

## Порядок интеграции

Грок начинает с `00_GROK_START_HERE.md`, применяет единственный патч к c671137, запускает полный набор и браузерные сценарии в своей среде, собирает сервер/UI и обновлённые шаблоны. Затем обновляет одну существующую пару agent/service-host, проверяет права ICMP и свежие отчёты. Повторная регистрация не требуется.

После обновления сервера старой вкладке может понадобиться ОДНА ручная перезагрузка для загрузки новой сборки интерфейса. Это не перезагрузка каждые пять секунд.

Не переносить автоматически все машины, не менять сохранённый внешний адрес, не удалять журналы состояния и не генерировать другую CA. Сохранить обычный независимый SSH-доступ. Браузерный обход и реальный ICMP в среде аудитора заблокированы; эти два пункта подтвердить на пилоте до расширения парка.
