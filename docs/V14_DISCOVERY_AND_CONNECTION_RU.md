# V14: подключение снаружи и актуальный список сервисов

Основа пакета: b969c6a34d3852687bd3aa3c73212ec4e183f55f. Это инструкция к новым исходникам, не сообщение об изменении боевой установки.

## Адрес: не только значение в агенте

Правильное значение для новых внешних подключений:

```
https://46.150.103.61:8777
```

Завершающий `/` допустим. Старый ошибочный `46.120.103.61` исправлен в общем bootstrap и первой настройке UI. Но у уже настроенного агента адрес берётся из сохранённого состояния, а при новой установке приоритет имеет выбранный доверенный профиль. Обновление бинарника не является ребиндом.

На странице «Добавить машину» теперь есть «Доступный агенту HTTPS-адрес». По умолчанию там внешний IP, рядом можно выбрать адрес из действующих настроек контроллера. Если контроллер по-прежнему хранит `https://192.168.12.128:8777`, этот LAN-адрес не навязывается новому внешнему профилю. Оба варианта профиля (автообъявление и одноразовый код) используют выбранный адрес.

Кнопка проверки сертификата проверяет загруженный сертификат контроллера. Она НЕ делает сетевой запрос к введённому адресу. Даже положительный результат не доказывает доступность с удалённого сервера.

## Если в сертификате нет внешнего IP

Нельзя просто отключить проверку TLS. Сертификат должен содержать IP в SAN и проверяться по CA, вложенной в профиль.

1. Грок собирает новый сервер. Проверяет фактический каталог состояния работающего контроллера. Сохраняет защищённую согласованную копию состояния. Завершает активные операции обслуживания перед остановкой.
2. Останавливает ровно этот контроллер обычным для текущего развёртывания способом. Не удаляет controller.lock и не запускает второй экземпляр.
3. Новым бинарником выполняет:

```sh
./monik-server tls-add-name --data-dir /ФАКТИЧЕСКИЙ/КАТАЛОГ/КОНТРОЛЛЕРА --name 46.150.103.61
```

4. Запускает прежний контроллер с прежними настройками и каталогом. Обновляет страницу «Добавить машину», повторяет проверку и скачивает новый профиль.

Команда требует существующие CA и серверный сертификат; не создаёт новую CA вместо потерянной. Сохраняет прежние DNS/IP-имена, CA и маршруты. Если IP уже присутствует, сертификат не меняется. С работающим контроллером команда отказывает по блокировке.

При отдельном reverse proxy важно проверить именно сертификат, который он отдаёт снаружи. Изменение внутреннего leaf не перенастраивает чужой TLS-терминатор. Нельзя подменять CA без согласованного изменения доверия агентов.

## Проверка маршрута до установки на удалённой Linux-машине

Профиль monik-discovery.json передать доверенным способом. Извлечь только публичную CA и проверить доступность:

```sh
python3 -c 'import json,pathlib; p=json.loads(pathlib.Path("monik-discovery.json").read_text()); pathlib.Path("monik-controller-ca.crt").write_text(p["ca_cert_pem"])'
curl --fail --show-error --connect-timeout 5 --max-time 10   --cacert monik-controller-ca.crt https://46.150.103.61:8777/health
```

Это не передаёт код или пароль. `-k` не применять. При ошибке остановиться и разобраться с портом, firewall, маршрутом и сертификатом. Проверка с самого контроллера не заменяет проверку с удалённой машины.

Для автообъявления открыть окно приёма в UI. Два бинарника agent и service-host одной сборки должны находиться рядом. После `setup` использовать выданный путь конфигурации; не удалять регистрацию уже настроенного агента.

```sh
sudo ./monik-agent setup --profile monik-discovery.json
sudo ./monik-agent service install
```

Подтвердить ожидающую машину по отпечатку. Проверить `listener_inventory_v1`, managed_ready, правильный URL, прежнюю/новую ожидаемую идентичность, свежую телеметрию и совпадение desired/applied. Наличие родителя `systemd --user` не заменяет испытание полноценной службы. Сохранить отдельный SSH/консоль провайдера, проверить перезапуск службы и загрузку ОС на одной машине, затем расширять парк.

## Почему рос список сервисов

Код сохранял всё найденное, но не сверял исчезнувшее с новым полным списком портов. На машине со сборками и тестами могут появляться временные слушатели. Точный состав ваших 38 записей здесь не проверялся. Смена PID сама по себе не создаёт новый сервис: серверная идентичность связана с машиной, адресом:портом и Host, не с PID.

Теперь отдельно учитываются наличие порта и результат HTTP. Два новых полных обхода, разнесённых минимум на минуту от первого отсутствия, подтверждают исчезновение. Перезапуск агента, отсутствие связи, урезанный инвентарь, старый пакет или HTTP 401/404/503 этого не подтверждают. При стандартном минутном обнаружении очистка представления не мгновенная.

Исчезнувшие, выключенные и не выбранные для обзора сервисы уходят из обычного списка и счётчика. При выключении существующей проверки сначала требуется подтверждение настроек агентом. На странице «Сервисы» и в подробностях машины есть «Показывать исчезнувшие». История, имена и запросы остаются; возвращение порта возрождает тот же ID.

**Включённый или закреплённый сервис не исчезает вместе со своей аварией.** Он остаётся с объяснением «порт не обнаруживается». Общая пауза машины также не удаляет ожидаемые сервисы. Для ненужного временного сервиса отдельно снимите «Проверять» и «В обзоре». Не надо выключать реальные важные проверки ради красивого счётчика.

Известный выключенный сервис по-прежнему не опрашивается HTTP через повторное обнаружение. Наличие проверяется по таблице сокетов ОС. Неизвестный порт при первичном распознавании может получить ограниченные HTTP/TLS-запросы, как и раньше.

## Порядок интеграции

Только новый пакет целиком: сервер/UI, затем агент и matching service-host. Предыдущие патчи не применять. Нет повторной регистрации работающего lan-host и нет автоматической замены его LAN-адреса. Грок запускает `scripts/verify-audit14.sh --with-browser` в своей среде и записывает фактические результаты. Большая часть текущих тестов использует временное состояние. Нативная загрузка Windows/Linux и полный restore всё ещё требуют отдельного допуска.
