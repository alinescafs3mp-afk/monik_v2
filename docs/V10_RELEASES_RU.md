# Monik v10: публикация обновлений без подмены предыдущего релиза

## Что изменилось

Подписанные комплекты теперь получают собственные неизменяемые каталоги и адреса по хешу содержимого. Импорт B не заменяет файлы A. Каталог, список файлов, доверие к обновлениям и результат импорта сохраняются одной транзакцией SQLite после проверки и подготовки файлов.

«Комплект опубликован» означает готовность подписанных файлов к выдаче. Это НЕ подтверждение установки на машины. Установка по-прежнему подтверждается агентом и служебным процессом отдельно.

## Порядок перехода с ce602d0

1. Сохранить полную защищённую копию данных контроллера: согласованную SQLite, TLS, ключ шифрования, настройки, каталог tuf и доверие. Полностью автоматического защищённого restore пока нет; встроенная копия одной БД не заменяет всё это.
2. Собрать и установить сервер вместе с UI из этого исходного кода. Существующие машины продолжают обычный мониторинг.
3. Один раз обновить старые агенты локальным защищённым способом, сохраняя конфигурацию, идентификатор, ключ и адрес. Для текущей пары это обычная согласованная установка агент + service-host; не использовать повторную регистрацию. Дождаться способности immutable_release_v1 в отчёте агента.
4. Импортировать проверенный подписанный комплект. Галочка зачисления корневого ключа разрешена только для первого доверенного набора, а не для обхода ошибки существующего доверия.
5. Старые строки каталога помечены «Старый формат». Для нового запуска обновления повторно импортировать исходный валидный подписанный комплект. Если подписи/метаданные истекли, нужен новый подписанный комплект, а не отключение проверки времени.
6. Выбрать одну совместимую управляемую машину, проверить её обычный резервный доступ и выполнить пробное развёртывание. Сохранённая операция, скачанные байты и подтверждённая новая версия являются разными стадиями.

## Чего не делать

Не удалять каталог tuf/trusted или строку release_trust ради повторного «первого» импорта. Не пересоздавать повреждённый ключ подписи. Не копировать новые файлы поверх старого каталога релиза. Не запускать два независимых контроллера с копиями SQLite. Не рассчитывать, что старый агент сам поймёт новый протокол адресов: для него действует явный запрет новых раскаток до однократного перехода.

Уже выданные старые задания используют прежние файлы: этот сервер их не перезаписывает. Но исходные сроки действия и ограничения старого механизма остаются. Новая версия сервера не обещает задним числом исправить старое выполнение.

## Сбои и место на диске

Если файлы подготовлены, а запись БД не удалась, может остаться непубликуемый каталог без ссылки из БД. Он не выдаётся агентам. Повторный явный импорт тех же байтов проверит и использует его. Автоматической уборки таких каталогов и общей квоты релизов пока нет. Не удалять ничего вручную при активном импорте/скачивании; сначала сверить ссылки каталога и заданий, сохранить резервную копию и остановить управление обновлениями на время согласованного обслуживания.

Ошибка подписи/проверки файла не заменяет ранее проверенный staging-файл агента. Наличие старого каталога не разрешает откат на устаревшие метаданные: журнал принятых версий сохраняется. Локальный откат по подтверждённому журналу предыдущей рабочей версии является другим действием.

## Границы

Этот раунд закрывает согласованную публикацию и адресацию релизов, но не независимое восстановление service-host, партии/canary, полный restore и длительную историю. Для настоящего удалённого сервера сохранять обычный SSH/консоль провайдера до прохождения нативной приёмки. Рабочие функции мониторинга, прочтения операций и экранные режимы остаются прежними.
