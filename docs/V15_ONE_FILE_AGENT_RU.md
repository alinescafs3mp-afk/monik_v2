# V15: установка агента одним файлом

После подготовки V15 Гроком на контроллере весь обычный сценарий для новой Linux-машины:

1. В «Добавить машину» нажать «Скачать агент: linux-amd64» (для ARM выбрать подготовленный arm64). Адрес по умолчанию: `https://46.150.103.61:8777`.
2. Перенести файл `monik-agent` на сервер и выполнить:

```sh
chmod +x monik-agent && sudo ./monik-agent
```

3. Дождаться строки `ГОТОВО`. После этого терминал можно закрыть. Машина уже зарегистрирована и прислала данные. Для показа на главной по-прежнему используется отдельная галочка машины.

Отдельные YAML, сертификаты, второй бинарник, команда регистрации, `service install`, `nohup` или оставленный открытым SSH не нужны. Внутри установочного файла уже находятся worker и service-host одной сборки, адрес контроллера, его публичная CA и одноразовое разрешение владельца. После установки они работают в штатной системной службе, а не под оставленным терминалом.

`chmod` нужен, потому что браузер/перенос файла обычно не сохраняет Unix-разрешение исполнения. Если оно уже выставлено, достаточно `sudo ./monik-agent`.

## Что именно подтверждает «ГОТОВО»

Установщик проверяет целостность и архитектуру всего пакета, настоящее TLS-доверие и идентичность контроллера, регистрацию машины, включённый автозапуск, действующий service-host и рабочий процесс. Сервер должен подтвердить два свежих отчёта с тем же процессом и применённой конфигурацией. Наличие процесса или флага managed само по себе не считается готовностью.

Во время работы видны четыре этапа. При ошибке выводится `НЕ ГОТОВО` с причиной. Если служба уже установлена, но связь не подтвердилась, это прямо сообщается: ошибка не называется успешной установкой. Сохранённая регистрация не удаляется.

## Одно разрешение на одну новую машину

Файл выдаётся владельцу после проверки входа, при необходимости с повторным подтверждением пароля. В нём одноразовый код на один час. Разрешение уже выдано при скачивании: отдельно открывать приём неизвестных машин или подтверждать кандидата после запуска не требуется.

Для следующего сервера скачать следующий файл. Не публиковать файл и не передавать посторонним: до использования он позволяет подключить одну машину. Постоянный пароль владельца и общий ключ парка в него не входят. Сам установщик на другой новой машине после расходования кода не зарегистрируется.

Повторный запуск на уже установленной и исправной машине проверяет её текущее состояние, не меняя бинарники, ключи или адрес. Он не служит способом принудительно откатить/обновить работающего агента. Для штатных дальнейших обновлений остаётся подписанный механизм Monik.

## Поддержка и ограничения этой поставки

Однофайловый вариант реализован для Linux amd64/arm64 с systemd, штатным `useradd` и `nologin`. Цель работает без установленного Go, Python, Docker или Node. Windows и Linux без systemd этим новым установщиком пока не поддерживаются. Их прежние варианты не удалены.

Подготовка и размещение шаблонов на контроллере выполняются Гроком один раз при развёртывании, а не вручную на каждом новом сервере. Шаблон должен совпадать со сборкой сервера. Никакие старые LAN-адреса существующих агентов автоматически не заменяются.

Полный V15 Go/Vue/браузерный прогон и настоящая установка/перезагрузка systemd не выполнены в среде аудитора. Перед выдачей готового файла Грок должен выполнить их и пройти один чистый Linux-пилот. Проверки формата файла и тесты отдельных функций не заменяют это испытание. Не считать первую удачную строку в терминале доказательством полного restore или готовности самообновления самого service-host: эти большие задачи остаются открытыми.
