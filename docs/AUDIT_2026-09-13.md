# Monik source audit and corrective implementation

Date: 2026-09-13. Reviewed baseline: `2515a91b34d3cbbd1b4a68f74513b5462c53145c`.

**Result: substantial corrective implementation, NOT approval of a complete v3 release.** This audit changed code, added regression tests, rebuilt the UI, and tested the source in an isolated Linux environment. It did not access, restart, rebind, upgrade, or otherwise change the owner's running installation. The public bootstrap URL is unchanged; persisted deployment configuration remains authoritative.

## 1. What was wrong, and what changed

| Area | Confirmed source defect | Correction and remaining boundary |
|---|---|---|
| History | Downsampling inserted a bucket into its own JSON `rows`, producing a recursive object and a failed response. | Non-mutating, acyclic buckets; independent extrema for numeric series; serialization failure returns a real HTTP error. |
| Historical time | Variable-width fractional UTC strings sorted incorrectly at exact-second boundaries. | Fixed-width UTC storage and an idempotent transactional legacy-time migration. Point queries never select a later sample. |
| Agent/service API | Storage structs leaked a credential verifier and used field names inconsistent with the UI; desired configurations could expose sensitive references. | Explicit public JSON fields and omitted credential/config internals; overview and machine APIs return real measurement summaries. |
| Ingestion | Partial writes could survive a failed report, repeat delivery duplicated observations, and buffered host samples were lost or confused with live contact. | One transaction for report data plus deduplication receipt; retry conflict detection, owner-scoped checks/jobs, retained historical host data, distinct current-contact handling. |
| Live ordering | An older session/report could rewind current metadata. | Compare the accepted live observation time as well as session/sequence; replay cannot refresh current state. |
| Command delivery | Marking a job delivered excluded it from later polls, so a lost response lost the command. | Delivered jobs remain retrievable until an actual receipt; persistent agent receipt journal, acknowledgements, expiry, and bounded batches. |
| Command results | An agent could acknowledge another agent's job; several handlers claimed success without performing the requested effect. | Transactional ownership checks, allowed states, idempotent terminal receipts, operation-specific committed telemetry/config evidence, and explicit rejection of unproven success. |
| Cancellation | Cancelling already delivered work implied it had been recalled from the agent. | Only never-dispatched pending jobs are cancelled. Delivered/cached work remains unresolved until evidence arrives. |
| Configuration | Unsupported scheduling, secret references and check methods were accepted as though applied. | Shared validation rejects unsupported values, validates config hash/revision, and preserves the last accepted configuration. Broader scheduling and base-revision CAS still need work. |
| Check pause | A service-specific pause could pause host monitoring. | Only the selected service's check definitions are paused. |
| Incidents | A nominal minute-long breach could confirm on the next sample; healthy observations did not reliably close service incidents. | Durable observed-duration streaks, gap handling, actual recovery evidence, three failed/two successful service checks. This is not the full versioned v3 rule engine. |
| HTTP probes | A malformed/truncated or over-limit body could pass, methods and IPv6 default ports were mishandled. | Bounded complete-body expectations, explicit configured status requirements, GET/HEAD-only probes, correct IPv6 address formatting, and regression cases for redirects/401/oversized/truncated responses. |
| Agent responsiveness | Discovery/check loops could monopolize telemetry; reconnect drained an unbounded amount of backlog. | Separate bounded discovery/check work, no overlapping runs, capped probe concurrency, bounded current-first spool draining. Collector calls still need full deadline and scheduling coverage. |
| Spool | Partially written reports could be exposed to the replay loop. | Private temporary files, sync and atomic rename; pending files excluded from enumeration and trimming. Persistent drop accounting remains open. |
| Update security | Bundle verification did not establish an independently enrolled trusted root; activation/restart paths were not backed by the required safe native lifecycle. | Unsafe update actions blocked at API/queued-job/worker/IPC boundaries. Old records are labelled untrusted. **Signed worker and service-host updates remain mandatory release blockers, not implemented by this patch.** |
| Rebind | A response could overwrite the active URL without candidate identity/readiness proof, a confirmed trial, or safe fallback. | Blind migration delivery/application removed; public rebind actions fail closed with a clear reason. Full prepared/armed/confirmed migration remains mandatory. |
| Secrets and stubs | Secret values could enter operation journals; rules, maintenance, retry and other actions had success-shaped stubs. | Secret replacement and unimplemented actions reject before persistence; legacy secret operations are redacted on reads. Historical plaintext already stored requires operator review/rotation, not a claim of secure erasure. |
| Admin boundary | Configured admin network restrictions were not enforced; logout and oversized/chunked responses needed better handling. | Enforced IP/CIDR checks on browser/admin routes using actual peer address, never arbitrary forwarded headers; CSRF on logout; bounded JSON bodies. Agent endpoints retain their separate authentication. |
| SSE/browser state | Initial streaming, reconnect gaps, session expiry and slow writes could leave the interface stalled. | Initial flush, finite write deadlines, expiry handling, resnapshot hints and non-overlapping visible-page polling fallback. |
| UI action feedback | Lost POST responses encouraged duplicate actions; errors disappeared, and completed-with-errors could look successful. | Session-persisted non-secret idempotency metadata, lookup of the original operation instead of blind resubmission, persistent unknown/error feedback, per-target outcomes and explicit unsupported states. |
| TLS renewal | Background renewal could lose the certificate's IP/DNS SANs and raced with expiry reads; separate leaf files could be torn across a crash. | Preserved SANs, atomic in-memory certificate, serialized renewal and a private atomically replaced `tls/leaf.bundle.pem`; legacy pair migration, malformed-CA checks and CA-expiry boundary. Native Windows crash durability remains untested. |
| Build truth | Tracked generated bundles could remain unrelated to reviewed Vue source. | Generated bundles are no longer source-controlled. `make ui`/`make all` and CI build the matching UI. A source-only server without assets returns an actionable 503 instead of silently serving stale UI. |

The original test suite passed before these corrections. Five initial targeted regressions were first observed failing on the old source (history cycle, JSON boundary, unsafe migration delivery, foreign receipt and lost job delivery); they pass on the corrected implementation. Passing the old suite was not evidence of product completeness.

## 2. Owner-facing UI changes

The overview now contains machine cards with CPU, RAM percentage and bytes, the most-filled local disk with its mount and capacity, average ping and loss, and compact HTTP service results. A correct zero remains zero; unsupported/missing/stale data remains visibly unavailable. HTTP 401 is an HTTP response, not an unreachable server; HTTP 503 is not healthy merely because a TCP connection exists. No response bodies or authentication secrets are copied into overview cards.

Opening a machine shows separate CPU, RAM, ping, packet-loss, filesystem and exposed-temperature graphs, current service outcomes, and desired/applied config state. All six 1/2/3/6/12/24-hour ranges are available. HISTORY fixes its absolute end time and does not jump back to LIVE. Point lookup shows its actual observation time/age; current inventory is explicitly distinguished from historical measurements. Peaks and gaps are retained rather than converted to smooth fictional health.

Views expose initial loading, refresh, empty, failed and stale states. Polling does not continually reconstruct input forms. Immediate UI reaction and durable server operation results are separate. A timeout after a mutation asks for the original operation's result and never blindly repeats the mutation. Existing unknown results can be recovered from the Operations page. Pending agent work remains pending, not successful because HTTP returned 202.

These are source and automated-logic changes. Visual browser acceptance on the author's environment was blocked by `ERR_BLOCKED_BY_ADMINISTRATOR`, including on the isolated loopback test fixture. No screenshot or actual production walkthrough is claimed. CI now includes a real compiled-UI/browser test against a synthetic local Go server. Its result belongs to the actual resulting commit and must be read in GitHub Actions, not assumed from the presence of the script.

## 4. Mandatory remaining work for Grok, in order

### P0: finish the actual managed-agent lifecycle before any release claim

Do not remove the fail-closed guards merely to make buttons clickable. Replace each guard only with an implemented path plus adversarial integration/native evidence.

1. **Trusted signed updates.** Persist an independently enrolled TUF root and versions/expiry policy, verify metadata/targets without trusting a key delivered by the same untrusted bundle, enforce platform/component/size constraints, serialize lifecycle operations, and implement staged worker and service-host replacement with native independent recovery. Verify local health and a fresh committed controller exchange before declaring success. Canary per OS, pause batches on failure, survive power loss at each boundary, and avoid rollback loops during controller/network outage.
2. **Native Linux and Windows managed installation.** Prove protected binary/state locations, restricted identities, service protocol, start before login, reboot, clean shutdown and recovery. A Windows executable that compiles is not proof of a working SCM service. Test service-host replacement itself, not only its child worker.
3. **Safe rebind.** Implement durable prepare/armed/ready/activating/confirmed/fallback state, monotonic generations, staged trust, identity/readiness verification, bounded trials, receipts, offline accounting and explicit endpoint retirement. An offline never-prepared agent cannot discover an unknown replacement address. Serialize rebind, update and trust changes. Physical controller relocation requires one authoritative writer and a consistent final state transfer.
4. **Secrets.** Keep secret values out of operation/idempotency/audit payloads and responses, then implement protected reference-based storage and delivery. Review any old `secret.replace` operation rows, jobs, logs and backups: read-time redaction is not secure erasure. Rotate credentials that were actually stored in plaintext. Do not expose real values in the corrective report.

### P1: monitoring and operational completeness

- Implement and test all advertised collector enable flags and intervals; add independent deadlines for native CPU/disk/temperature calls. Ensure saved UI configuration matches executed behavior. The current worker deliberately accepts only its implemented 5-second host/report/check interval and 2-second probe timeout, but other collector configuration is still limited.
- Complete configured health paths, multi-check/vantage identity, body/JSON policies and native discovery evidence. Do not merge independent check incidents just because they share a service. Docker/NAT/virtual-host discovery coverage must remain explicit, not inferred from visible listeners.
- Implement base-revision compare-and-swap for multi-tab configuration edits and explicit per-target reconciliation. Persistent desired state, a delivered job and applied evidence are distinct. Preserve owner overrides and display names during inventory refresh.
- Finish rule versions, hysteresis/policy changes, maintenance, incident search and historical service states. Current corrected observed-duration logic is a smaller evaluator, not the entire v3 contract.
- Implement tested minute/long-term aggregates, retention jobs and indexed historical search. This patch truthfully exposes raw 48-hour data; it does not silently claim the proposed 30/180-day resolution exists. Measure WAL/disk/query behavior at the intended fleet size and bound event/receipt growth.
- Complete database PLUS controller config/identity/CA/master-key backup, protected restore, restored-job reconciliation, and old/new writer fencing. The current backup operation explicitly says database snapshot only, restore not verified.
- Finish credential/trust rotation, typed diagnostics, one-shot timeout/cancellation semantics, sustained resource limits and spool loss accounting. A generated signing tool and helper unit tests are not release acceptance.

### P2: finish UI behavior against real agents

Run `tests/browser/audit.py` in CI, inspect desktop/mobile screenshots and extend it to the implemented features. Add genuine online and offline agents; test changed form state during live refresh, persistent selection, no-response retries, per-target partial failure, history gaps, old rule boundaries, accessibility and reconnect. Add service drill-down graphs and indexed incident history rather than showing a time selector that does not query the selected interval.

Telegram stays deferred. Do not expand this into remote shell execution, host reboot, application restart or automatic remediation.

## 5. Upgrade and operator notes

1. Back up the existing application data directory and local configuration with protected permissions before running this source. This audit did not perform an upgrade on the owner's machine.
2. Build from the reviewed checkout with Go matching `go.mod` and the locked frontend packages. Run `make all` (or `make ui` before a custom server build). Generated UI assets are intentionally not in Git. Use CI build artifacts only after inspecting their exact commit and results.
3. First startup performs the fixed-width timestamp migration transaction. On a large database this can take a write lock; test a copy and schedule a maintenance window rather than assuming zero migration cost. Keep the previous consistent backup; do not mix old writers with the migrating server.
4. TLS now uses `tls/leaf.bundle.pem` as the canonical complete leaf pair, mode 0600. Preserve the entire TLS directory and controller secrets in a protected backup. Legacy separate leaf files may remain for migration, but renewal updates the canonical bundle. External reverse proxies must manage their own configured certificates; do not assume they read this internal bundle.
5. Deploy server and worker changes together under a tested local procedure. Older workers that claim completion without matching committed evidence will now receive an explicit rejection; this is safer than false success, but it is a protocol-coordination consideration. Automatic update is not available as a deployment shortcut yet.
6. The default bootstrap address has not been replaced by an observed live IP. Existing stored endpoints remain untouched. Do not re-enroll or reset identity merely to adopt this source.
7. Do not declare the application releasable until P0 and the native acceptance gates pass. `IMPLEMENTATION_STATUS.md` supersedes the earlier overly optimistic implemented labels.
