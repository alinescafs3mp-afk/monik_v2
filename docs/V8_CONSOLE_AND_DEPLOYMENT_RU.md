# Monik v8: экран, имена сервисов, SSH и первый удалённый агент

## Что поменялось в обзоре

ТВ-режим по умолчанию использует 10px вместо прежних 14px, то есть примерно на 29% меньше. Можно выбрать 12 или 14px. Один раз сбрасывается только ТВ-плотность, не пароль, не сессия и не выбранные машины/сервисы. Меню телевизора выровнено сеткой и ограничено по высоте; обычный режим телефона не уменьшается вместе с ним.

Красная рамка и первый приоритет относятся к проблемам показателей машины и к ошибкам выбранных для обзора проверяемых сервисов. Ошибки остальных наблюдаемых сервисов остаются видны своим счётчиком, но не управляют этим приоритетом. Пауза и отсутствие измерений не выдаются за отказ приложения. Потеря контакта выделена отдельным уровнем. Прочтение инцидента не делает показатель исправным. Новая проблема возвращает телевизионную страницу к началу списка.

Имя сервиса редактируется в «Сервисах» и в подробностях машины. URL, имя процесса, идентификатор, история и запрос не меняются. Ошибка сохранения видна; конфликт с другой вкладкой не затирается.

## SSH-консоль: отдельный доступ, не привилегия агента

Кнопка «Консоль» открывает страницу подключения выбранной машины. Доступ нужен **от контроллера Monik до действующего SSH-сервера**, а не от браузера до агента. Это не туннель сквозь NAT, не установка SSH и не выполнение shell-команд через канал мониторинга. На Windows потребуется отдельно установленный и настроенный SSH-сервер; его работа здесь не проверялась.

На контроллере один раз создайте `<DataDir>/console-targets.json`, доступный только администратору и служебной учётной записи контроллера. Рекомендуемые права 0600. Не кладите его в публичный репозиторий. Пример структуры:

```json
{
  "targets": {
    "EXACT_EXISTING_MONIK_AGENT_ID": {
      "host": "203.0.113.10",
      "port": 22,
      "username": "operator",
      "host_key_sha256": "SHA256:REPLACE_WITH_INDEPENDENTLY_VERIFIED_FINGERPRINT"
    }
  }
}
```

Пример намеренно не работает, пока не заменены все значения. В `host` нужен IP, а не доменное имя. В файле нет SSH-пароля или приватного ключа. В `DataDir` нужен реальный каталог работающего контроллера, а не путь из случайного примера.

Отпечаток проверяется по уже доверенному доступу к серверу, например непосредственно на нём:

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
```

Это **публичный** ключ сервера, не приватный ключ владельца. Самостоятельно полученный по недоверенному соединению отпечаток не доказывает правильный сервер. При его изменении консоль отказывает до отправки SSH-учётных данных. Для ротации сначала независимо сверяют новый ключ и затем меняют локальное соответствие.

После настройки откройте консоль, подтвердите недавний вход владельца и введите отдельный SSH-пароль либо приватный ключ. Ключ с паролем поддерживается. Данные не сохраняются в Monik и не вставляются в адресную строку. Приватный ключ проходит через доверенный контроллер для аутентификации; это не client-only аппаратная подпись и не агентное forwarding. Не используйте это на недоверенном контроллере.

Терминал умеет интерактивный ввод и изменение размеров. Многострочная вставка требует подтверждения. Лимиты: один сеанс на машину, четыре на контроллер, час общей работы, десять минут без ввода, 16 МиБ вывода. Отзыв браузерного входа или изменение соответствия закрывает соединение при следующей проверке, примерно в пределах пяти секунд. Повторного автоматического ввода/переподключения нет. Закрытие окна не гарантирует остановку уже запущенных удалённых программ.

SSH-консоль требует HTTPS до самого Monik либо повторного TLS-соединения от доверенного proxy к Monik. Plaintext upstream за TLS-терминатором в этой версии отклоняется. Не отключайте проверку Origin/TLS, чтобы обойти этот отказ. Ввод и вывод терминала не пишутся в журналы мониторинга; записываются только метаданные соединения. Временное присутствие данных в памяти неизбежно.

На телевизоре с сохранённым входом owner доступны те же права владельца. Это не ограниченная viewer-учётка. Не оставляйте такую сессию на общедоступном устройстве.

## Первый настоящий удалённый Linux-сервер

Процессные проверки проведены: отдельные собранные агент и supervisor работают не от root, собирают настоящие CPU/RAM, переживают остановку/перезапуск, перезапускают убитого worker, сохраняют идентичность и отправляют буфер после восстановления приёма сервером. Это **не** доказательство установки через systemd, запуска после загрузки ОС или восстановления после отключения питания. Сначала одна машина, с сохранённым независимым SSH-доступом.

1. Обновите сервер и UI из одной сборки. На удалённой машине используйте агент и service-host той же сборки. Проверьте контрольные суммы/происхождение. Не заменяйте контроллерный URL встроенным старым IP; он должен быть реально доступен с удалённой машины и соответствовать сертификату. LAN-адрес домашней виртуалки сам по себе для удалённого сервера не подходит.
2. Получите доверенный профиль подключения из своего контроллера. Для автоматического подключения откройте окно приёма новых машин и затем сверяйте отпечаток заявки. Для первоначальной установки от root задайте в профиле `state_dir: /var/lib/monik-agent`, `config_path: /var/lib/monik-agent/agent.json`. Не используйте приватный `/root` или произвольный общий каталог для службы.
3. Сохраните оба бинарника рядом в каталоге установки, понятном администратору. Выполните команды с абсолютными проверенными путями (ниже `./` означает именно этот каталог):

```sh
sudo ./monik-agent setup --profile ./trusted-discovery-profile.json
sudo ./monik-agent service install --config /var/lib/monik-agent/agent.json
systemctl status monik-agent --no-pager
```

Установка создаёт/проверяет отдельную учётную запись `monik`, настраивает закрытые права только выбранного каталога состояния, помещает неизменяемый service-host в `/usr/lib/monik`, активный worker в `/var/lib/monik-agent/bin` и запускает службу. При существующей учётной записи убедитесь, что это именно выделенная учётка мониторинга, а не чужой обычный пользователь.

4. Подтвердите заявку в веб-интерфейсе после сверки отпечатка. Дождитесь первого **свежего** отчёта, правильных версии/возможностей и совпадения желаемой/применённой конфигурации. Не путайте одобрение с фактическим поступлением измерений.
5. Выполните локальную диагностику:

```sh
sudo -u monik /usr/lib/monik/monik-agent doctor --config /var/lib/monik-agent/agent.json
sudo journalctl -u monik-agent -n 100 --no-pager
```

`doctor` не ждёт одобрения бесконечно и не гарантирует внешнюю связность: это локальная проверка. Не публикуйте полные журналы, конфигурации и ключи без проверки на секреты.
6. Выберите несколько действительно нужных сервисов. Убедитесь, что выключенная проверка не отправляет запросы, выбор для обзора не меняет мониторинг, имена переживают rediscovery, ошибки выводятся по фактическому результату.
7. До раскатки на остальные машины оператор отдельно проверяет `systemctl restart`, повторный запуск после перезагрузки и восстановление связи. Сохраняйте обычный SSH/консоль хостинга как аварийный канал. Не проводите эти испытания автоматически на рабочей машине без подходящего окна.

### Не маскируйте ошибки установщика

Установщик отклоняет небезопасные пути, символьные и жёсткие ссылки и неподходящие права. Не исправляйте это `chmod 777` и выдачей root рабочему агенту. Исправьте размещение/владельца целевого каталога. При ошибке переустановки старая служба могла уже остановиться; проверьте журнал и повторите осознанно либо восстановите проверенную сборку/состояние. Полного автоматического отката всех шагов установки ещё нет.

Самообновление service-host с независимым восстановлением, управление партиями и полный restore контроллера остаются незавершёнными. Не испытывайте их на единственном удалённом доступе. Windows-права/SCM требуют отдельной доводки: успешная кросс-компиляция не делает эту платформу принятой для unattended-развёртывания.
